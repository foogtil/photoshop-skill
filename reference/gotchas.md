# Photoshop 自动化与检查注意事项

修改 JSX、排查 Photoshop 或核对色彩/方向时阅读。格式和 RAW 解码细节见 [photo-formats.md](photo-formats.md)。
以 `scripts/photoshop_tone.py` 和 `scripts/photo_review.py` 为实现依据，不在此复制第二套脚本。

## 调整层与实际生效

曲线层使用 ActionManager 的 `make → using: adjustmentLayer → type: curves → adjustment` 描述符。
各 `curvesAdjustment` 包含 composite/red/green/blue 通道引用和 horizontal/vertical 点坐标。
直接把调整字段放在图层描述符上或用整数代替通道引用，不能代替该结构。

自动复合曲线使用明度混合模式，避免亮度调整附带改变彩度；传统手动曲线保留原行为。
自然饱和度和饱和度通过独立 vibrance 调整层应用。
可选 temperature/tint 生成通道曲线；它们是有限的 RGB 偏移，不能当作 Camera Raw 白平衡或开尔文色温。
必须查看实际导出及像素变化；图层存在、COM 调用返回或 dry-run 成功均不证明参数已经生效。

ExtendScript `.jsx` 与 UXP `.psjs` 是不同环境；不要把 UXP 的 require/batchPlay 写进 DoJavaScript。
某个命令失败可能来自描述符结构、对象或文档状态，不能由此推断整个脚本 API 不受支持。

## 色彩、曝光与方向

- Pillow 应用 EXIF 方向、将嵌入 ICC 的照片转换到 sRGB，再测量缩略图。无效 ICC 会在准备阶段报错。
  无 ICC 照片按近似 RGB 解释，Photoshop 工作空间可能影响这类源图。
- Photoshop 打开普通图片时处理方向，RAW 解码基线已应用相机方向，不再额外旋转；导出须检查方向和尺寸，避免方向标签重复应用。
- 工作文档转为 RGB 和 sRGB，保留支持的 8/16 位精度；JPEG 在最后转为 8 位，并将透明区域合成到白背景。
  PNG/TIFF 保留透明度及支持的位深；输出嵌入 ICC，不保留可编辑调整层。转换失败按照片报错。
  PNGSaveOptions 在实机中可能省略 ICC；`png_profiles.py` 只写入 sRGB 的 iCCP 配置块，保留图像数据、透明通道和位深，避免 Pillow 重存 RGB16 导致精度降低。
- RAW 使用同一份全尺寸 16 位 sRGB TIFF 解码基线进行统计、Photoshop 调色和处理前对比。
  不调用 Camera Raw 界面再次开发，不用内嵌 JPEG 缩略图代替 RAW 解码；原 RAW 和 XMP 不写入。
- 全透明像素不参与曝光、彩度统计；预览背景仅帮助观察透明图片，不表示输出被加上该背景。
- 默认不降低红绿高光制造固定冷调，不以全图 RGB 均值推断白平衡。
  找不到可信灰白区域时，通过视觉和明确风格决定冷暖；不要把场景本来的颜色“校正”为灰色。
- 自动曲线保护端点并按中间调诊断曝光；亮图或黑白图仍须视觉检查。
  已剪裁的信息无法重建，直方图不能区分有意高调、低调、雾气与错误曝光。

## 检查报告的含义

`--preview-only` 写原图预览和计划，不启动 PS；该阶段没有处理后风险结论。
实际导出后写 comparison 图片与 review.json。检查目录默认位于输出根目录的 `_ps_review`。
同一目录中的报告和同名预览会被后续运行更新，候选比较应分开保存。

风险统计基于方向/ICC 一致的缩略图，不是全分辨率逐像素检测，也不是美观评分。
RAW 的处理前一栏为固定解码后的图像（RAW render）；解码使用拍摄白平衡、关闭自动增亮，不能将它与相机内嵌 JPEG 的差异算成调色效果。
细小高光、纹理和局部肤色需要放大成品检查。当前提示包括：

- 暗部或高光剪裁相对原图增加超过 1 个百分点；原图已有剪裁不会单独视作新风险。
- 某 RGB 通道剪裁增加超过 2 个百分点；彩度大幅增加。
- 原图可用中性色样本出现非预期色差；采用同位置像素色差增量的第 90 百分位，避免局部相反偏色在全图平均中抵消。
  明确 temperature/tint 时仍需人工检查肤色和中性色。
- 暗图继续明显变暗、效果近乎不变、尺寸变化或缺少 ICC；适用时检查透明度和位深。

统计阈值用于提示复查；白背景、灯光和明确的艺术效果需结合照片判断。
`--strict-review` 对被标记照片返回非零，不会自动回调或判定哪个候选更好看。
每条记录的 `visual_review_required` 提醒继续视觉判断；`pass` 表示没有触发当前技术阈值。

## 源图与会话安全

- Python 在打开 PS 前准备整批任务；准备失败会停止。输出保留相对子目录。
- 旧输出默认跳过，overwrite 才替换；JSX 保存前再次检查。不要并发写相同输出，存在检查与保存不是原子操作。
- 每个输出均与整批已扫描源图路径及文件身份比较，避免递归输出或硬链接覆盖另一张源图。
  检查路径不得覆盖源图/计划导出，检查目录若是普通文件会被拒绝。
- 已在 PS 打开的源图会被拒绝，以保护未保存编辑。只关闭本次打开的批处理文档，不保存回原图。
- finally 恢复原对话框模式与活动文档；成功状态在导出和关闭后记录，Python 验证输出存在且非空。
- COM 只对 `RPC_E_SERVERCALL_RETRYLATER`（`0x8001010A`）有限重试。
  持续忙碌时检查 PS 对话框/操作，不强杀进程。
- 连接前检查 PS 进程。本次启动且无剩余文档的会话正常 Quit，异常路径同样清理；
  原有会话默认保留，keep-open 保留新会话，quit 也可退出原有空会话。COM 释放本身不会退出软件。
  退出失败会报告，不能当作完成。

## 编码与状态

`js_lit` 使用 ASCII 转义的 JSON，包含 Unicode 路径及 U+2028/U+2029；COM 接收 Unicode 字符串。
通过 PowerShell 传递 JSX 时明确使用 UTF-8；BOM 不能替代正确的读写编码。

PS 每个任务返回一行 OK 或 URI 编码的 ERR。Python 按任务顺序匹配，拒绝遗漏或未知状态。
任一照片导出失败返回非零；旧输出不能代替本次成功结果。
